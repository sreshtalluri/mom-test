## Problem Statement

`sreshtalluri/mom-test` ships seven self-contained Mom Test skills (router, prep, check-questions, next-question, debrief, roleplay, outreach) plus ~29k words of framework in `docs/`. Today each skill is a one-shot: nothing a founder learns in one conversation changes what the agent says in the next, and nothing helps mid-call. The goal is to make this the go-to customer-discovery toolkit for founders who work inside coding agents (Claude Code, Codex, Cursor), found via GitHub.

The nearest neighbour, `getagentseal/founder-playbook` (534★), is a single reference-doc skill. The 2026 tool market (Perspective AI, Koji, Frank, Diaform, User Intuition) automates the interviewer. The Mom Test's own Chapter 8 argues learning only transfers when the founder is in the room. Nobody coaches the founder live or keeps a compounding evidence base inside the agent. That is the gap.

## What Makes This Cool

Four things, in priority order:

1. **Discovery memory that changes what the agent says next time.** A `discovery/` folder of plain markdown in the founder's own repo. `mom-test-prep` reads it ("you already killed A2 in interview 4; A5 is the riskiest one left"). `mom-test-debrief` writes to it. Evidence compounds.
2. **Evidence gate ("Discovery CI").** A founder inside Claude Code asks "build a deposit feature." `/mom-test-gate` reads `discovery/`, finds the assumption the feature rests on, and answers: "Evidence: 2 compliments, 0 past behavior, 0 budget signals. Build anyway, or run 2 conversations first?" Never blocks. Only a coding-agent-native toolkit can do this.
3. **Live paste coach.** During a call the founder pastes the last few lines with `F:`/`C:` prefixes. `mom-test-next-question live` returns four labelled lines: `Signal`, `Why`, `Say next`, `Don't say`.
4. **Roleplay league.** Persona packs by industry and difficulty, scores saved to `discovery/practice/scores.md`, a share block, and a next-persona recommendation. The one part of the loop a non-founder can use today, and the easiest thing for strangers to contribute.

Codex's cold read independently landed on 1 and 2 and called the user's pick of "persistent discovery memory" the center of gravity (D3). The user added 4 mid-session.

## Constraints

- Skills stay self-contained: everything a skill needs lives inside `skills/<name>/` (SKILL.md plus bundled files such as `templates/`, `seed/`, `personas/`). Skills get symlinked or copied out of the repo; no reads of `docs/`, other skills' dirs, or any top-level dir.
- No database, no new file format. Markdown in the user's repo, tracked by default so it's diffable and greppable.
- The agent coaches; it never runs the interview for the founder (premise #2).
- v1 live coach is paste-driven; no transcript integrations (LiveKit / whisper.cpp are later options).
- Install stays zero-config: clone + open, `./install.sh`, or `/plugin`.
- Author is not currently a founder; primary user is a stranger on GitHub. Polish of the first 60 seconds matters more than depth.
- Prompt-only. Shell is limited to `cp`, `grep`, `ln`, `sed` one-liners. Anything a prompt can't guarantee is a manual-test criterion, not a hard rule.

## Premises

All five agreed by the user (D6):

1. Differentiation vs founder-playbook is **workflow** (prep → live → debrief → memory → practice), not a better reference doc.
2. The agent coaches the founder; it never runs the interview.

4. Live copilot v1 is paste-driven; transcript integrations later.
5. For GitHub founders, a 60-second README demo + zero-config install beats any new feature.

### The `discovery/` folder (all markdown, tracked by default)

```
discovery/
  README.md            what each file is; id scheme; tag syntax; how skills use them; tracked-vs-gitignored tradeoff
  assumptions.md       | id | assumption (falsifiable) | segment | kill condition | status | evidence | updated |
  segments.md          | interview | role | attrs | top problem (unprompted) | highest rung |
  decisions.md         | date | decision | verdict | justified by |
  interviews/
    _template.md
    YYYY-MM-DD-<role-or-company>.md      (-2, -3 suffix on collision)
  practice/
    scores.md          | date | persona | difficulty | total | lowest two | highest rung |
```

**Rules that make this implementable by a prompt:**

- **IDs.** Assumptions are `A<n>` where `n = max existing + 1`. IDs are never renumbered. Row order in `assumptions.md` is priority order and may be rearranged freely; IDs stay stable.
- **Evidence lives in interview files only.** A rung-labelled fact is written once, inside the interview file, as `[A3+] rung 13 "I built a spreadsheet with macros"` (supports A3) or `[A3-] rung 8 "we tried that and turned it off"` (contradicts A3). No separate evidence file; `grep -rn '\[A3[+-]\]' discovery/interviews` is the index. The `evidence` cell in `assumptions.md` holds the interview basenames that mention the id.
- **Riskiest assumption** = the first row in `assumptions.md` whose status is `UNTESTED` or `WEAKENED`. If none, the list is exhausted and callers fall back to their pre-memory behavior and say so.
- **Status vocabulary** (global, in `assumptions.md`): `UNTESTED · SUPPORTED · WEAKENED · KILLED`. Debrief's per-conversation verdict (`SUPPORTED / WEAKENED / KILLED / UNTOUCHED`) merges as: `KILLED` is sticky; within one `record` call, any `WEAKENED` beats any `SUPPORTED` regardless of order; across calls, the later call wins; `UNTOUCHED` never changes the cell. The `updated` cell is the date of the last change.
- **Segment link.** `assumptions.md` has a free-text `segment` cell (e.g. `derm office manager`) matched against the `role` column of `segments.md`. `status`'s 3-in-one-segment check groups by `role`. Gate counts within the assumption's `segment` when set, else cross-segment and says so.
- **Roleplay is not evidence.** Interview files with `source: roleplay` are never written; roleplay writes only `practice/scores.md`. `gate`, `status`, and `prep` count only real interviews.
- **Write discipline.** Append-only: `interviews/`, `decisions.md`, `practice/scores.md`. `assumptions.md`: rows may be appended by `gate` or `record`, never deleted or reordered by a skill; in-place edits allowed only to the `status`, `evidence`, and `updated` cells. `segments.md`: rows may be appended or updated. Nothing else is ever rewritten.
- **Slugs** are role-or-company (`2026-09-04-derm-office-manager.md`), never a person's name; names appear only inside the file. If a file with the same date + role already exists, `record` asks "`<basename>` already covers this. Write anyway as `-2`? [y/N]"; default N, so re-running on the same debrief writes nothing.
- **Location** is `./discovery/` relative to the working directory. No override.

**`interviews/_template.md` contents:** a header block (`date`, `role`, `segment attrs`, `source: call | notes`), `## Facts` (one tagged line each, `[A<n>±] rung <r> "quote"`; untagged facts allowed), `## Verdicts` (`A<n>: SUPPORTED | WEAKENED | KILLED`), `## Surprises`, `## Follow-up` (names, commitments with dates).

### Components

| Component | Type | What it does |
|---|---|---|
| `skills/mom-test-memory/` | new skill + bundled dirs | `SKILL.md` plus `templates/` (the six files above) and `seed/` (a complete derm-clinic `discovery/` with 4 interviews, 5 assumptions in mixed states, segments, one decision, two practice scores). **`init [--example]`**: `cp -r` templates (or seed with `--example`) into `./discovery/`, creating only files that don't exist and listing what it skipped. Asks one y/N: "keep `discovery/` tracked in git? (default yes; it contains real names and quotes)"; on N, appends `discovery/` to `./.gitignore` (create if missing; skip if present). Then offers to add two marker-prefixed lines to the project's `CLAUDE.md` (create if missing; skip if marker present): "`discovery/` holds customer evidence. Before building a feature, suggest `/mom-test-gate`." **`status`**: counts assumptions by status, interviews, segment consistency (debrief's 3-in-one-segment rule), names the riskiest assumption, and re-derives each `evidence` cell from grep of `[A<n>±]` tags, flagging any disagreement. **`record`**: uses the most recent debrief in this conversation; if none, asks for notes and runs `mom-test-debrief` first. Writes one interview file per conversation (batch debriefs produce several, in listed order), updates `assumptions.md` cells per the merge rule, appends/updates `segments.md` rows. Reports which files changed. |
| `skills/mom-test-next-question` (edit) | existing | Adds **`live` mode**: `/mom-test-next-question live <paste>`. Input is 3–20 lines prefixed `F:` (founder) or `C:` (customer); unprefixed lines are treated as customer and the output says so; fewer than 3 lines falls back to normal mode and says so. `Signal:` classifies the **last `C:` line**; `Why:` may reference earlier lines. Output is a literal four-line template: `Signal: <one of the 10 statement types> (<band>)` · `Why: …` · `Say next: "…"` · `Don't say: "…"`. Bands everywhere (live, normal mode, gate) are exactly `none / problem-real / solution-wanted`; the existing skill's `weak` band is removed. If `discovery/` exists, `Say next` prefers a question that tests the riskiest assumption. Description updated to mention live mode. |
| `skills/mom-test-gate/SKILL.md` | new skill | Input: a feature or decision. Classifies it: **solution-stage** if it names a feature or product to build; **problem-stage** if it names a problem or segment to pursue; asks one y/N if unclear. Reads `discovery/`. Maps it to one or more `A<n>`; if none match, drafts a falsifiable assumption + kill condition and offers to append it as `UNTESTED`. Counts distinct interviews with a `[A<n>+]` rung-8+ fact, within the segment named for that assumption in `segments.md` when one exists, else cross-segment and says so. Reports counts by band, strongest `+` quote and strongest `-` quote. Verdict is computed on the mapped assumption with the fewest qualifying interviews, evaluated in order: **run 3 conversations first**, quoting the kill, if any mapped assumption is `KILLED`; **build** if ≥3 qualifying interviews and (problem-stage, or solution-stage with ≥1 rung-16+ fact); else **build as experiment** if ≥3 qualifying interviews but solution-stage with no rung-16+; else **run N conversations first** with `N = max(1, 3 − qualifying interviews)`. Never blocks. If the founder accepts a verdict, appends a row to `decisions.md`. If no `discovery/`, says so and offers `init`. |
| `skills/mom-test-prep` (edit) | existing | If `discovery/` exists: read `assumptions.md` and `segments.md`; scary question = the riskiest assumption (or pre-memory behavior if the list is exhausted, saying so); list what's already known about this segment so it isn't re-asked; cite interview basenames. |
| `skills/mom-test-debrief` (edit) | existing | If `discovery/` exists: load `assumptions.md` first and use its `A<n>` IDs in §5 instead of inferring assumptions; tag every rung-8+ fact in §1 with `[A<n>+]` or `[A<n>-]` where one applies; emit `top problem (unprompted)` and `highest rung` so `record` can fill the `segments.md` row. Ends with "Record to `discovery/`? [Y/n]" and on yes runs `record`, reporting files changed. If no `discovery/`, offers `init`. |
| `skills/mom-test-roleplay/personas/` | bundled files | `README.md` (schema, the difficulty table, contribution steps, and a note that hidden facts are readable on disk, honor system) plus **5 seeded packs, one per difficulty, spanning industries** including healthcare at difficulty 3. Path: `personas/<industry>/<slug>.md`. Frontmatter: `name`, `industry`, `role`, `difficulty` (1–5). Body: hidden facts (dated incidents with costs, current solution, past attempts, spending, decision path, constraint, urgency trigger, volunteered feature request + motive, emotional nerve). Whether they have the problem and whether they decide is implied by difficulty, not a separate field. |
| `skills/mom-test-roleplay` (edit) | existing | Accepts `<persona-slug>` or `random [industry] [difficulty]`. Match industry first, then nearest difficulty; if no industry match, generate a persona as today, assign it a difficulty from the table, name it `generated:<role-slug>`, and say so. Never echoes the persona file before the debrief. Difficulty table (duplicated verbatim from `personas/README.md`): **1** has the problem, answers directly, is the decision-maker · **2** has the problem, needs one anchor to get specific · **3** tolerated problem, one tangent per turn, real top problem is adjacent · **4** buried problem, flatters when pitched, not the decision-maker · **5** no real problem, warm, non-decision-maker, volunteers a feature idea. At debrief: if `discovery/practice/scores.md` is missing, asks "Save practice scores to `discovery/practice/`? [Y/n]" and on yes creates it with the header row (duplicated verbatim in this SKILL.md; full `init` not required); then appends one row. |

Shows last 10 scores, trend, weakest category (most frequent entry in `lowest two` across the last 10 rows), personas whose best score is ≥ 46 ("beaten") vs. < 46, grouped by difficulty, and a one-line share block. Next persona: `< 46` same or easier; `46–59` same; `≥ 60` one harder; delegates to `/mom-test-roleplay random <difficulty>`. |

### Sequencing

1. `mom-test-memory` (`templates/`, `seed/`, `init | status | record`). Hand-test: `init --example`, run `status`; then debrief a pasted transcript, `record` it, check `assumptions.md` cells and the interview file; run `record` again and confirm it refuses.
2. Wire `mom-test-prep` and `mom-test-debrief` to memory. Hand-test: prep before and after one recorded interview; scary question should change.
3. `live` mode in `mom-test-next-question`; remove the `weak` band. Hand-test with 10 pastes.
4. `mom-test-gate`. Hand-test on seed data: a matching solution-stage feature, a matching problem-stage decision, and a non-matching feature.
5. `personas/` (README + 5 packs) and `mom-test-roleplay` edits. Hand-test `random healthcare 3` and `random fintech 2` (no fintech pack → generated).
6. `mom-test-league`.
7. README top, router, `install.sh` check, this repo's `CLAUDE.md`.
8. Bump `.claude-plugin/plugin.json` to 0.2.0; validate with `./install.sh` into a scratch dir plus `python3 -c 'import json; …'` on both manifests; commit; push.

## Success Criteria

Manual tests, since everything is prompt-driven:

- A stranger can clone, run `/mom-test-memory init --example`, follow the README loop, and see `/mom-test-gate` produce a real evidence verdict inside 5 minutes.
- After two recorded interviews, `/mom-test-prep` names a different scary question than before the first, citing the interview basename that changed it.
- `/mom-test-next-question live` returns the four labelled lines in 10 out of 10 manual pastes, and `Don't say` is non-empty in all 10.
- `/mom-test-gate build X` with an empty `discovery/` explains what's missing; with seed data and no matching assumption, it drafts one; with a matching solution-stage feature lacking rung-16+ evidence, it returns "build as experiment."
- `/mom-test-memory status` flags a deliberately mismatched `evidence` cell.
- `/mom-test-memory record` run twice on the same debrief writes once and refuses once.
- `/mom-test-roleplay random healthcare 3` loads the seeded persona and appends one row to `discovery/practice/scores.md`; `random fintech 2` generates one and still appends a row.
- `/mom-test-league` shows a trend and recommends the next persona after two runs.
- A new persona file that follows the schema is picked up with no code change.
- `./install.sh` fails if a skill's frontmatter name doesn't match its directory, and links cleanly otherwise.
